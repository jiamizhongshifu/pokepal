## 反馈处理与保存规则（R2，已确认）

- 仅钟师傅处理项目收到的反馈，不将联系方式、孩子资料或真实反馈提交到公开仓库。
- 问题关闭时记录关闭日期和到期日期（关闭后 30 天）；每周检查并清理到期的运营者管理记录，包括另存副本。不要仅清理台账而保留对应正文。
- 未关闭问题每 30 天复核，记录是否仍需处理及下次复核日期。已无需处理的问题应关闭，进入结案保存期。
- 家长可通过原邮件或微信渠道提出更正/删除，按具体对象处理并反馈结果；不要求孩子证件或原声。
- 邮箱/微信服务商的系统备份、安全日志及留存按其规则处理，不承诺所有平台副本即时删除。
- 本次确认的是运营规则，不是自动化任务或邮箱清理授权。本轮没有设置定时任务、读取通信内容或删除消息。实际处理时应核对范围并遵守工具授权要求。

## 真机记录（R4）

使用 `device-matrix.csv`；未知项写“待测”，不要以桌面改分辨率代替设备实测。iPad/安卓只打开网页，不重新打包。每次记录网页版本、设备/浏览器、地区/网络，使用合成昵称。

按顺序检查：首次须知与头像 → 首次捕捉 → 英语主线奖励 → 回岛播放 → 故事 → 麦克风拒绝后的替代操作 → 后台 2 分钟再返回 → 刷新/重开存档 → 备份与隔离恢复 → 更新 → 暂停试用。连续体验约 15 分钟，记录发热、持续卡顿和声音等待。

优先普通安卓 Chrome 与 iPad Safari，再补目标海外网络；微信内置浏览器未通过时明确提示使用外部浏览器。任何操作不得要求上传真实儿童录音或清除真实存档来“试一下”。

- 前一已验收生产基线为 `2026-10-18T02:15:11.045Z`，部署 `c16f9231-1055-450b-b9b2-192de4cb3eae`，带三条家长说明页。将它保留为候选回退基线，不采用不含说明的更早版；当前生产及新规则差异见发布记录。
- 保留当前产物/源码指纹及部署 ID；本地连续构建不可覆盖最后可用的生产证据。

- 只有明确要求发布时执行 `npm run release:publish`：它要求干净的 main，再次准备/核对生产，然后上传；上传结束仍需版本、资源、须知/进入/存档冒烟验收。
- 发生存档丢失、异常上传、白屏或无法退出时先停止发新链接，记录版本和可复现步骤。不要让家长清空浏览器数据作为第一处理手段。

- 只有验证兼容后才决定 Cloudflare 回退；不兼容时优先修复前进。平台回退、旧标签页 Service Worker 更新、本机数据恢复是三件不同的事。

## 人工问题台账（R9）

使用 `issues-template.csv`，真实条目只保存在受控本地目录，不提交 GitHub；代码仓库中仅保留空模板。家庭以 F01/F02 编号，联系方式留在原私密渠道，不复制到台账。

分类：听不懂、看不懂、找不到、声音、性能、存档、隐私、学习参与。严重度：

- S0：数据泄漏/丢失、未经说明上传、无法退出——暂停扩量，优先处理。
- S1：主线无法完成、反复无声/白屏——首批使用前修复或排除受影响组合。
- S2：需要多次家长代点、局部布局/措辞不清——记录发生步骤和复现频率。
- S3：愿望/新增玩法——先观察，不挤占英语启蒙与可靠性修复。

问题闭环：收到 → 复现/补充最少信息 → 修复 → 原设备复核 → 关闭。记录自愿再听/指认/表达、家长代点情况；不将能量多或玩得久当作学习效果。
