# 宝可梦英语小岛：玩法对比与后续优化计划

日期：2026-10-16。状态：R0–R4 的首版功能已按下方记录接入，新增 R2–R4 已通过本地逻辑与浏览器检查；家庭体验与 iPad 性能验收仍未完成。

## 当前开发进度

| 阶段 | 本轮结果 | 验收边界 |
|---|---|---|
| R0 | 自动观察兼容系统减少动态效果，用户已确认 iPad 镜头启动 | 多伙伴新事件另行回归；不把镜头通过当成全部玩法通过 |
| R1 | 伙伴野餐、种植到分享、库存幂等、发现手册回忆已接入 | 家庭三次体验观察尚未记录 |
| R2 | 稳定个体喜好；双伙伴滚球/休息；单伙伴陪玩；独立停靠点；可拒绝取消；最近 18 条共同经历 | 当前采用体型通用动作，不是为全部物种制作专属动画 |
| R3 | 三组微环境、六件可撤回设施，固定位置；设施和喜好参与活动排序 | 无自由施工；实际 iPad 帧率和拥挤场景仍需测试 |

## 1. 产品方向

把产品发展为「和宝可梦共同生活的英语启蒙小岛」。下一阶段优先让伙伴、环境、故事和英语课程产生联系：孩子做了一件事，伙伴有所回应，小岛留下变化，熟悉的英语在另一种情境里再次出现。

核心体验：观察伙伴 → 自主选择帮忙或一起玩 → 环境发生变化 → 伙伴回应 → 下次自然再遇到相同表达。

这次对比基于官方产品资料及当前项目代码，没有实际游玩三款产品。竞品事实、我们的设计推导、待验证目标分别说明；不把机制相似视为适合幼儿或具备教学效果的证明。

## 2. 三款游戏分别借鉴什么

《动物森友会》以《集合啦！动物森友会》为比较对象。《动物园之星 2》按 Frontier 在 Xbox 官方商店的产品页比较，该页列出 2026-10-13 发售，未用一代玩法代替二代。

| 维度 | 集合啦！动物森友会 | Pokémon Pokopia | 动物园之星 2 |
|---|---|---|---|
| 基本循环 | 探索、收集、制作、布置，与岛民相处 | 帮助宝可梦、运用能力、建设和恢复环境，结识更多伙伴 | 建设栖息地、满足动物需求、观察行为，经营和扩建 |
| 世界如何回应 | 居住与装饰变化、邻里交往、时节与收藏积累 | 宝可梦帮助建设，环境改善带来新的相遇 | 环境与设施影响动物需求满足、群体活动和行为 |
| 长期动力 | 属于自己的家园、熟悉的邻居、个人收藏 | 共同建设的成果与伙伴关系 | 更丰富的动物行为、更好的环境与经营成果 |
| 我们最值得借鉴 | 稳定关系、生活小惊喜、可留下回忆的收藏 | 宝可梦参与解决具体问题，能力与场景产生因果联系 | 用行为表现需要，让场景设施真正被使用 |
| 需要舍弃或大幅简化 | 现实时间等待、错过活动的压力、大量重复采集 | 复杂材料链、大规模自由建造、持续扩张负担 | 财务与员工管理、多参数环境面板、复杂施工操作 |

事实来源：[动森官方玩法介绍](https://animalcrossing.nintendo.com/new-horizons/explore/)、[任天堂动森入门](https://www.nintendo.com/jp/ichikara/acbaa/index_en.html)、[任天堂 Pokopia 产品介绍](https://www.nintendo.com/en-gb/Games/Nintendo-Switch-2-games/Pokemon-Pokopia-2915161.html)、[Frontier 发布的动物园之星 2 商店说明](https://www.xbox.com/en-US/games/store/planet-zoo-2/9p2578z09zh5)。表中“借鉴”和“简化”是本项目的设计判断。

对本项目而言，三者的结合点是：**熟悉的伙伴 + 有用途的环境 + 能看懂的行动结果**。例如，孩子摆了一张遮阳垫，喜欢安静的伙伴会过去休息；它邀请孩子坐一会儿，于是 “I need a rest.” 有了真实用途。

当前站点选择已经考虑属性和习性，不能简单描述为“所有宝可梦行为一样”。主要缺口在于：这些差异尚未充分变成孩子可记住、可影响、可再次体验的关系。

当前种植闭环已经存在，不应重复立项。当前闲置镜头也已经实现，不应当成新功能再次开发。上一轮本地验证不能替代真实 iPad 验收。

## 4. 面向 3–6 岁的共同规则

NAEYC 的适宜性实践强调以游戏、个体优势和具体情境支持学习。[来源](https://www.naeyc.org/resources/position-statements/dap/definition) 以下为本产品的设计选择，需要通过家庭试用验证：

- 先看懂动作，再听懂词，再尝试表达；发展水平优先于按年龄强制分组。沿用现有初阶/进阶设置。
- 每次主动邀请只提供一个清楚的小目标，选项通常为 2–3 个；允许忽略、拒绝、换伙伴或稍后再来。
- 英语帮助完成互动，不作为获得食物、照顾、捕捉和继续游戏的硬门槛。不强制开麦或写字。
- 初阶可以听词、指认、看示范；进阶可以理解短句、选择回应、尝试说话。同一玩法支持不同程度。
- 普通操作不恢复全局双语字幕条；英语提示出现在互动对象附近，可重播、可关闭。故事屋继续完整中英共读。
- 没有离线饥饿惩罚、作物枯死、关系衰退、连续签到或限时错过压力。日常参与奖励沿用现有规则。
- 同屏最多一个主动请求，不叠加多个急迫提示；观察镜头不得延长家长设置的使用时长。
- 主要操作保留点击替代拖动；先以至少 48 CSS px 点击区域设计，再在实际 iPad 上检查遮挡和误触。

## 5. 分阶段安排

按版本验收推进，不并行铺开全部系统。下列工作量用于比较范围，不是工期承诺：S 为局部修改，M 为跨模块闭环，L 为需要新交互与内容制作的阶段。

| 顺序 | 优先级 / 工作量 | 交付范围 | 英语融入 | 进入下一阶段的条件 |
|---|---|---|---|---|
| R0：可靠互动 | P0 / S–M | 验收避让、站点占用、离页返回、镜头接管；补多人站点与取消处理 | 避免语音说完但角色未到、动作错配 | 真机完成核心交互，无卡住、重复扣物品或镜头争抢 |
| R1：一起准备野餐 | P0 / M | 一条种植→收获→选择伙伴→分享→回应的完整体验 | 请求帮助、给予、感谢；复用已有课程和故事 | 孩子能看懂行动结果；零树果、单伙伴、离线均可正常处理 |
| R2：伙伴有自己的生活 | P1 / M–L | 稳定喜好、少量共同经历记忆；滚小球和一起休息两种双伙伴事件 | 轮流、邀请、休息、拒绝与情绪表达 | 两个伙伴协调行动、可取消退出，不靠堆需要条制造负担 |
| R3：可以改变的小家园 | P1 / L | 三种微环境、首批六件功能设施、固定安全摆放点 | 位置、物品和动作词，语义由真实摆放结果支撑 | 布置后行为确实改变；不会堵路、穿模或明显损伤 iPad 性能 |
| R4：发现与生活故事 | P2 / M | 三条跨区小事件；发现本记下共同经历；事件驱动观察镜头 | 同一表达换伙伴、换物体后再现，连接故事与复习 | 英语提示能迁移，家长能区分参与和独立理解；可自然结束 |

依赖关系：R0 → R1 → R2 → R3 → R4。R1 验证失败先缩小或修正体验，不用增加更多物种和玩法掩盖问题。美术只为当阶段可验收的动作和场景服务。

### R0：先保障角色真的能完成互动

1. 为“去往站点—等待—开始—完成—取消”明确状态和超时退出；遇到占用可等待或去其他站点，不重复争抢。
2. 双伙伴站点必须有两个不同的接近点和动作位置；所有入场路径均考虑大体型与水生角色。
3. 点击其他功能、离开家园、关闭弹窗、切入后台时有明确的保留/取消规则；返回不重置正常生活轨迹。
4. 用户输入立即中断观察镜头；跟随、主动照顾、学习和观察镜头有唯一控制权。
5. 原有避让已修改的部分以回归验收为主，只有发现新问题才追加改动。

验收案例：迎面对走、同点争抢、三只以上聚集、站点取消、不同体型混合、水陆边界、离页再返回。不能只靠角色位置的静态截图判断无抖动。

### R1：首个完整样板「伙伴野餐」

复用现有种植区和野餐设施，首版不增加货币、不扩大地图、不新增独立小游戏入口。

| 环节 | 孩子看到的变化 | 互动及英语 |
|---|---|---|
| 发起 | 一个伙伴带着小篮子来邀请 | 可以一起准备，也可以稍后；邀请不能反复打断 |
| 帮忙 | 已拥有的伙伴拿水壶或使用合适动作浇种植地 | “Help, please!”；缺少水系宝可梦也能完成，不能凭空生成杰尼龟 |
| 收获 | 使用已有生长计时；成熟树果进入已有篮子 | 现有库存可以直接开始野餐；未成熟时允许去做其他事情 |
| 分享 | 选择一只已拥有的伙伴，递给它一颗实际树果 | “Here you are!”；只扣一次库存，拒绝和取消不扣 |
| 回应 | 接住、闻一闻、吃、开心地靠近等可辨动作 | “Thank you!” / “Yummy!”；只播与当前动作匹配的表达 |
| 留下经历 | 发现本出现“今天一起分享了树果” | 记录共同经历，不直接标记英语已掌握；可选打开《一颗苹果，谢谢你》 |

复用现有 `magic-words` 故事《一颗苹果，谢谢你》。课程连接优先复用 `garden-helper`、`snack-discovery`、`kind-words`；故事中已有给予和感谢语境。

注意树果不是苹果：当前课程中有 apple，但场景使用的是宝可梦树果。新增 berry 对应图片、解释和火山离线配音后才作为可考察词；不得把任意树果直接教成 apple。首轮主表达只选“Help, please!”和“Thank you!”，给予和喜欢作为自然回应，避免一次塞入全部内容。

先为六只常见伙伴制作明确的动作差异，供拥有它们的存档使用；其余物种用经过校验的通用动作。玩家只有一只伙伴时同样可玩。角色动作按骨架/体型复用，不为 388 只分别扩写全套对白。

验收：零库存有清晰去向；满库存不丢失产物；连续点击不重复消耗；退出后不重复发奖；伙伴中途忙碌时有替代处理；离线语音完整；安静模式照样能操作。

### R2：让“它记得我、也认识其他伙伴”可见

- 物种层：复用属性、体型、运动方式和当前习性，确定适合的设施与动作。
- 个体层：增加少量稳定喜好，例如喜欢球、喜欢阴凉、喜欢安静陪伴。标明这是游戏中的个体偏好，不把设计值当成官方设定。
- 关系层：只保留最近少量有意义的共同经历，例如上次一起野餐、一起玩球；下次在合适情境回应。保存版本和迁移明确，不记录孩子原始语音。
- 双伙伴行为先做两种：轮流滚球、一起休息。各自有角色、等待和退出位置，不能只把两只模型放在同一点播动画。
- 主动邀请使用“需要—请求—等待—回应”过程；孩子不回应时角色会自行继续生活，不持续求助、不降低好感。
- 喜欢某种食物可以有不同表情和感谢动作；首轮不增加复杂营养和口味数值，不因为投喂非最爱食物惩罚孩子。

英语对应现有 `our-turn`、`friends-together`、`rest-time`、`angry-pause` 等课程。允许 “No, thank you.” 和 “I need some space.” 成为有效选择，而不是错误答案。

### R3：用微环境改变活动，而不是继续堆模型

先在五个既有功能区内重组空间，首批六件功能设施采用固定安全摆放点，可替换、可撤回，暂不做自由施工编辑器。

| 微环境 | 首批设施 | 预期行为变化 | 英语机会 |
|---|---|---|---|
| 果园与野餐角 | 采收篮、分享桌 | 收获后带到桌边，伙伴有序围坐 | berry、water；请求、给予、感谢 |
| 树荫与安静角 | 遮阳垫、矮树丛 | 爱安静的伙伴选择休息、躲太阳、邀请陪坐 | tree、under；“I need a rest.” |
| 浅水与游乐角 | 浅水踏石、滚球轨道 | 适合水域的角色涉水；陆生伙伴在岸边协作、轮流推球 | water、ball；“My turn!” / “Your turn!” |

装饰必须有明确用途、可达路径、容量和动画停靠点。树木与石头优先用于围合空间、遮阴和引导路线；花朵继续自然散落，不恢复小花圃和独立浇花模式。

后续可以加入访客，但“来到岛上参观”与“已拥有”必须视觉区分。访客不能进入已拥有列表、不能冒充种植助手；孩子想留下它时进入既有指定捕捉流程，继续遵守捕捉与进化规则。访客不作为本阶段核心闭环的前置条件。

### R4：从一次小游戏走向可重复的小生活

首批三条跨区事件：树果分享日、轮流玩小球、陪伙伴休息。每条连接一个故事、一组既有课程内容和一次不同情境的再现，允许分几次完成，不绑定现实日期或连续登录。

- 发现本增加小岛经历和伙伴照片；复用现有入口，不继续增加主导航按钮。
- 故事看完后可以选择“去岛上试试看”；玩过的场景也可提示一个相关故事，均不强制跳转。
- 观察镜头优先观看刚被孩子影响的事件，再轮转其他伙伴；仍遵守当前闲置触发、中断、减少动态和家长设置。
- 家长可见的是“听过／有帮助完成／独立理解／尝试表达”的证据，不给孩子贴“聪明、落后”等标签。
- 天气与时间只营造变化；不要求孩子深夜上线，也不以连续看屏幕等待解锁。

## 6. 英语学习如何进入每一次迭代

课程负责有顺序地介绍，故事负责理解情境，小岛负责实际使用，复习负责隔一段时间换形式再现。四者共用词句标识和证据规则，不各自新增一套进度。

| 环节 | 可记录 | 不应推断 |
|---|---|---|
| 听到旁白或点重播 | 接触过某词句 | 已经理解 |
| 跟着手势、发光提示完成 | 在帮助下完成互动 | 独立听懂 |
| 没有答案提示，听到请求后在合理选项中完成 | 本次独立理解的证据 | 永久掌握、所有情境都会 |
| 点击“我说好了”或检测到声音 | 尝试表达 | 发音正确、说了目标句 |
| 换物体、伙伴或情境后再次完成 | 新情境下的理解证据 | 自动等同口语能力 |

自由玩耍默认不考核。可选“听一听帮个忙”才进入清晰的理解机会，并始终提供重播和帮助；点击帮助后记录应降为辅助完成。动作恰好一致不能自动当成语言测验结果。

词句按内容清单审核并生成火山离线配音。先复用已有录音，新增词句完成语义、画面、字幕、音频和离线包检查后才能投放；不要为了覆盖全部物种产生大量几乎相同的付费语音。

## 7. 技术落点与验收边界

| 范围 | 首选现有落点 | 本轮实施时需要注意 |
|---|---|---|

持久化个体偏好与共同经历前，先明确旧存档默认值和迁移；不要恢复离线需求惩罚。先完成一个事件的数据流，再判断是否有必要抽象通用事件框架。

每个版本至少验收：新存档/旧存档、一个/多个伙伴、触摸误点、重复点击、离页返回、后台恢复、离线使用，以及 iPad 横竖屏的按钮与模型遮挡。

性能先记录真实 iPad 基线，再分别用少量和拥挤角色场景比较。可暂以稳定 30 FPS 为设计目标，但机型与实际测量确认前不承诺达标；调整远处动画与模型等级优先于减少玩家已拥有的宝可梦数据。自动镜头不能用频繁切换掩盖帧率问题。

本文件原始方案基于资料与代码核查；最新实施状态见开头。当前仍不宣称真机性能或教学效果已经通过验证。

## 8. 第一批执行清单与效果判断

原始首批顺序如下；用户现已要求继续推进后续阶段，按当前进度表执行：

1. 复测当前移动/镜头修复，记录实际 iPad 的重叠、卡住与误触。
2. 定义野餐事件的入口、参与角色、库存扣除和中断恢复，跑通一只伙伴的最小路径。
3. 完成递果与回应的画面，加入两条主表达，接入既有课程/发现本和火山离线语音。
4. 覆盖库存、重复点击、离线和旧存档的必要测试；实机走完一次完整体验。
5. 用现有家庭测试做三次观察，再决定是否进入 R2；这是可用性反馈，不是教育效果实验。

观察重点：孩子是否知道伙伴想做什么、是否能自主选择并完成、是否注意到行动后的变化、是否愿意再次和同一伙伴互动，以及换一个场景后是否仍理解熟悉表达。家长提示次数、错误触发和中途卡住比总游玩时长更值得记录。

不把在线时长、捕捉数量、完成动画次数、播放配音条数或签到连续性当成英语成效。真实语言发展还需要长期、跨场景观察，不能由短期家庭试用直接证明。

暂不排入近期：继续大规模扩图、增加更多世代来替代玩法深度、复杂建造/经营、在线多人、自由生成聊天、强制语音评分，以及独立浇花模式。当前优先用现有角色和场景做出可被孩子感知的关系与学习进阶。
