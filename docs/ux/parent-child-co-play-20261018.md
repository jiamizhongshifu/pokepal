# 从儿童独立操作到亲子共同体验

日期：2026-10-18。状态：已完成首批本地实现（学习记录文案、课程帮助暂停、点心亲子样板、家长事实摘要）；后续扩展仍为提案，见末尾验收记录。

依据：本地当前源码、现有试用说明及本次用户反馈。当前工作区包含尚未发布的改动；本文不代表线上状态或真实家庭体验验证。以下陪伴方式是待验证的产品设计假设，不是教学效果结论。

## 1. 重新定义使用场景

**核心使用者仍然是 3–6 岁儿童，体验设计的单位扩展为亲子关系。宝宝决定探索什么，家长参与回应，宝可梦把两个人带进同一个情境。**

我们希望家长体验到的魅力，不只是“孩子会点按钮了”，而是看到孩子的选择被世界回应、英语能用于分享和求助，以及孩子愿意表达自己的想法。

三个角色：

- 宝宝：选择伙伴、动手探索、听声音、自由表达，也可以只观察或拒绝。
- 家长：一起发现、回应分享、示范轮流、在需要时提供帮助；不是默认代点者或监考者。
- 宝可梦：提出具体需要、示范语言、对动作作出可见反应，连接屏幕中的体验与现实生活。

鼓励陪伴不等于必须全程陪玩。家长暂时离开、不懂英语、没有打开陪伴提示时，已有儿童流程仍可正常完成，奖励和进度不受影响。

## 2. 需要覆盖的真实场景

| 场景 | 宝宝需要什么 | 家长需要什么 | 产品应该如何响应 |
|---|---|---|---|
| 初次一起进入小岛 | 快速认识喜欢的伙伴，知道能做什么 | 明白产品主线及如何陪伴 | 家长完成必要说明后，把控制权交给宝宝；第一段体验只安排一个明确的小发现 |
| 大人坐在身边，一起玩一小会儿 | 自己操作，也能向大人分享 | 知道此刻说什么、做什么 | 在分享、求助、轮流等自然节点邀请一次；其余时间留给两个人交流 |
| 大人在附近，偶尔参与 | 不因等家长而卡住 | 回来后迅速理解刚才发生什么 | 不设家长必答步骤；在家长中心给出简短事实摘要 |
| 睡前或安静时共读 | 充分看图、听故事、讲自己的经历 | 控制节奏，听到孩子的想法 | 保留手动翻页与停顿，故事问题不要求正确答案，不催促继续 |
| 从屏幕转到吃点心、收玩具等生活活动 | 把刚听过的话用在真实关系中 | 一条马上能做、无需准备的建议 | 提供一个可选的离屏延伸，不要求回应用打卡证明 |
| 祖辈或英语不熟悉的大人陪伴 | 获得同样温暖的回应 | 不被英语能力门槛挡住 | 中文动作提示、英文可点读；大人用中文回应也成立 |

## 3. 对照现有流程的审计

| 业务环节 | 当前已有基础 | 从亲子使用角度看到的缺口 | 迭代方向 |
|---|---|---|---|
| 初次进入 | `Welcome.tsx` 有家长试用说明、头像选择、初始伙伴引导 | 家长知道怎样开始，但缺少简短、具体的陪伴示范 | 在既有家长说明中增加“让宝宝选，你来回应”的示例，不另建儿童必经教程 |
| 学英语首页与学习地图 | `TaskBoard.tsx` 以推荐课程为主，其他学习方式和记录分层；地图承担阶段进度 | 家长难以快速理解这一站在现实生活中有什么用 | 复用课程 `homePlay`，在按需帮助中呈现一个具体亲子动作；不要把地图变成家长报表 |
| 听、认与主线习题 | `LearningLesson.tsx` 有重听、解释、慢一点、自动流转及声音失败提示 | 轻松自动过题与亲子讨论节奏可能冲突；应用内提示不等于家长帮助 | 保留自动流转；主动打开陪伴提示时暂停，明确“接着玩”恢复。家长自然说话不会被自动识别为暂停请求 |
| 说一说、写一写 | 跟读允许先听、不做发音评分；已有书写和帮助机制 | 家长容易把设备没听到、笔迹识别问题理解为孩子没做到 | 优先区分设备、资源和输入问题；给出“我先示范，你想说再说”“用手指一起画一次”等可选支持，不把代做记为掌握 |
| 一起玩与照顾伙伴 | `IslandLivingPanel.tsx` 已有玩球、泡泡、跳跃、休息等直接互动；`useTogether.ts` 管理回合 | 目前“一起”的角色主要是宝宝与宝可梦，家长没有清晰的自然参与位置 | 给已有玩法加入屏幕外角色：宝宝给伙伴传球，大人接一句“My turn”；宝宝分享，大人回应感谢。无需新增家长控制器或逐轮确认 |
| 故事屋 | `Stories.tsx` 已有双语、手动翻页、页面暂停与“一起演一演”，结尾有提问和家庭实践 | 不是没有陪读能力，而是亲子邀请与具体页面关系仍可强化；结尾建议集中在折叠内容中 | 复用现有停顿，只在最合适的一页邀请一个动作或一个开放问题；不额外弹窗、不重复加一排问题 |
| 小日记 | `GuidedDiary.tsx` 有问题引导、跳过、原声保存、家长代写；强调保留孩子原话 | 家长主要承担记录工作，回应孩子的环节较弱 | 先邀请大人听完并回应；若以后保存大人寄语，与宝宝原话分开标注。网页版当前不提供云端转写，不以新转写服务作为依赖 |
| 结算与休息 | 课程结算以“看看下一站”为主，能量 toast；休息页区分昼夜并展示所有伙伴 | 结算主要反馈应用进度，家长较难带走一个真实发现 | 主按钮保持不变；可选带走一句生活用语。详细总结放家长中心，休息页不再安排学习任务 |
| 家长中心 | `Parent.tsx` 已有“今天可以这样陪伴”、阶段、学习记录及设置分区 | 陪伴建议基于当前课程；现有记录不能重建亲子互动，也不能证明宝宝独立完成 | 从“发生了什么 → 可以怎样陪 → 下次试什么”组织首屏，数据明细继续下沉 |
| 试用反馈 | `docs/trial/parent-first-session.md` 已询问解释/代点、主动表达和故障 | “陪伴成功”与“界面迫使家长救场”容易混在一起 | 分开记录自然共同参与、操作解释、内容示范、故障处理；无需孩子原声或家庭录像 |

### 需要优先澄清的记录语义

源码中的“未使用应用内提示”和“家长没有帮助”是两件不同的事。`Parent.tsx` 已解释熟悉记录的限制，但“累计独立指认”等名称仍容易让家长读成真实的独立完成。

后续应统一标注为“未使用应用内提示的指认”等可核验事实。听过不等于听懂、选择正确不等于会说、停留较久不等于困难、没说话不等于不愿表达。家长是否示范过，只能来自可选的家长补充，不能由点击轨迹猜测。

## 4. 一个值得先做完整的样板

**优先选择“树果点心时间 → 分享 → 家长回应”的连续情境。** 当前已有 `snack-discovery`、`LessonPicnic`、岛上分享和生活短句，可以把英语主线与亲子关系连接起来，改动范围比新建亲子系统更小。

1. 宝宝选择喜欢的伙伴，进入当前点心课程；家长不需要再做一次课程选择。
2. 宝宝听、认、把点心放进画面里的篮子；操作及语音继续沿用现有逻辑。
3. 只在分享节点提供一次可跳过的邀请：“也把一份点心指给身边的大人看看吧。”大人可回应“谢谢你”，英文示范按需播放。此句为提案文案，实施时需补齐配音。
4. 宝可梦对分享动作作出清楚的接收与开心反馈。大人的真实回应不靠语音识别判定，不要求点“家长已完成”。
5. 结算仍以“看看下一站”为主；岛上分享维持可选。家庭也可以离开屏幕，在下一次真实点心时间试用一句话，无需马上准备食物。
6. 家长稍后查看一句事实摘要和一个建议，例如“今天听过 apple，在点心活动中完成过选择。下次吃点心时，可以让宝宝选一份分享。”只有实际记录支持时才展示对应事实。

这是可分支的体验，不要求每次把课程、岛屿、故事、日记和现实活动全部串完。父母没有参与或宝宝不想分享时，课程仍正常完成。

## 5. 交互设计约束

- 每个时刻只有一个儿童主动作。亲子邀请应依附当前物品、角色或故事停顿，不在全局再挂一个常驻面板。
- 陪伴提示放在既有帮助入口或模块标题右侧；不新增独占一行的“怎么玩”，不增加首页入口竞争。
- 英文示范、宝宝录音、课程语音、岛屿对白需要互斥；家长打开说明或暂停时不被自动翻页带走。关闭说明不擅自重放整个教程。
- 物品要与语言指向一致：说分享就有被分享的东西，说轮到你就清楚显示轮次；反馈来自宝可梦的反应，能量不是每次亲子互动的理由。
- 反馈描述具体行为，例如“你把点心分给伙伴了”。不虚构“你今天很勇敢”“你已经掌握”，不因为陪伴时长或父母参与给予额外进度优势。
- 家长设置、数据维护仍保留家长保护入口；简单的共读、重听和陪伴建议不应反复要求家长验证。
- 不要求双人账号、双设备、开麦或开启摄像头。无需自动识别父母是否在场，不记录被动家庭对话。
- 鼓励亲子关系不只写“爸爸妈妈”；界面可用“身边的大人”，兼容祖辈及其他照护者。

## 6. 建议实施顺序

| 顺序 | 交付范围 | 完成判据 |
|---|---|---|
| P0：可信记录与陪伴节奏 | 核对独立/帮助/掌握文案；统一帮助打开后的暂停与恢复；保留系统故障与儿童回应的区别 | 应用记录不暗示识别到了家长帮助；暂停不漏题、不重复奖励；无音频不记为听过 |
| P1：一个亲子样板 | 做完整“树果点心时间”的一次邀请、图声反馈和可选生活延伸；复用现有入口与资产 | 宝宝可独立完成；大人无需英语基础即可参与；拒绝邀请、无成人、提前退出均不阻塞；小屏与深色主题没有新增遮挡 |
| P2：扩展到共读和轮流玩 | 选两本现有故事强化一处角色演绎；给玩球增加可选的现实轮流示范 | 不新增逐步确认；手动翻页与自动模式均可控；每次只给一个邀请；家长操作次数不因陪伴设计增加 |
| P3：家长能看懂的回顾 | 首屏提供真实发生的小事、一个陪伴建议；允许家长可选补充观察；再考虑日记寄语 | 各事实能追溯来源；应用事件与家长观察分开；可跳过、删除，无敏感内容自动上传；未有数据时不编造总结 |

不建议这一轮先做亲子任务排行榜、家长陪玩积分、每天必须共同打卡、长篇能力诊断、自由 AI 育儿问答或新的双人操作模式。这些不能直接解决“此刻怎样一起玩”的问题，并会增加复杂度或不必要的判断。

## 7. 用种子家庭验证方向

建议先安排 5–8 个家庭做探索性体验，覆盖不同年龄、不同英语熟悉程度的陪伴者；这个规模用于找交互问题，不用于宣称学习效果。

首轮只观察一个样板，后续再次体验时再看是否自然愿意重用。家长不需要上传录像、录音、照片或日记；用去标识的文字描述即可。

| 观察问题 | 如何记录 | 如何解释 |
|---|---|---|
| 家长能否自行看懂怎样参与？ | 是否需要开发者解释，具体在哪一步 | 用于判断引导清晰度，不给家长评分 |
| 宝宝是否仍掌握操作权？ | 家长自然回应次数与被迫代点的位置分开记 | 家长点击更少不等于陪伴更少 |
| 是否发生了屏幕外的共同回应？ | 指给大人、轮流、分享、交谈中的一个具体例子；也可记“没有” | 不强求说英语，不把照着做当作自然表达 |
| 宝宝在哪里需要支持？ | 页面、声音是否成功、发生的动作、家长提供的帮助 | 先排除设备与操作问题，不自动归因为语言能力 |
| 是否感受到伙伴在回应？ | 家长和宝宝能否说出伙伴刚才做了什么 | 判断画面、声音和动作是否指向同一件事 |
| 能否轻松结束？ | 离开是否保留进度，有无催促或失落性惩罚 | 成功退出也是好的体验，不用时长越长越好作指标 |

验收记录区分浏览器功能检查、真实设备表现、家庭观察和长期学习效果。前三项也不能直接证明第四项。公开反馈继续遵守现有私密渠道和保存规则；本提案不新增埋点、云端分析或数据承诺。

## 9. 首批实现与验收

- 学习记录：家长中心及发现手册不再把“未用应用内提示”简称为宝宝独立完成。明确应用无法判断家长帮助；旧存档字段和统计算法保持兼容，没有重置已有学习记录。
- 课程帮助：打开帮助后暂停 `LearningRound` 的自动流转，并取消本题拥有的语音。关闭后保持暂停，点“接着玩”才恢复；若本题语音被打断，恢复时重播。适用于复用该组件的主线、复习及初阶听读；不宣称已统一所有旧小游戏的异步跳题逻辑。
- 陪伴建议：课程顶部既有帮助里可查看该课的家庭实践建议，不新增常驻一行或家长确认步骤。
- 点心分享：课程完成后，三个盘中的食物变成可点选的分享入口。点选后伙伴收到对应食物、点头与爱心反馈，并说 `Thank you!`。一次成功的中文邀请鼓励指给身边的大人看；后续分享只说感谢，不反复讲解。
- 分享可跳过，可重复。不增加能量、答题、跟读或家长参与记录。既有英文播放计数可以增加，它表示实际开始播放，不能解释为掌握或完整听完。
- 家长首屏：展示当天首次完成的新课程和接触过的词；优先用当天最近首次完成的课程给出一个生活建议。没有新完成时回到当前课程建议，不虚构家庭观察。
- 配音：新增火山中文录音 1 条，约 30 字；完整清单恢复并校验为 56,156 条，网页构建验证 4,096 个配音包。本次没有生成 iPad 或安卓发布包。
