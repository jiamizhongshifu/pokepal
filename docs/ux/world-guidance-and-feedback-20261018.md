## 目标

宝宝能自己发现下一件有意思的事，听懂操作，看到行为的结果，并逐渐把英语用于照顾伙伴和表达自己。成功包括主动休息与自由探索；不以延长在线时间为目标。

借鉴手游的目标呈现、镜头调度、就地教学、动作反馈和成长表现。产品应围绕一条稳定体验组织：

**发现伙伴的事情 → 听到有用的英语 → 做一个简单动作 → 世界发生对应变化 → 留下成长痕迹 → 自选下一站或休息。**

每一站都要能回答：伙伴为什么需要这句话？宝宝要点什么？点完发生什么？下次在哪里还能用？

## 1. 视觉引导：一个画面明确一件事

采用三层视觉权重：

1. **当前动作**：一个最醒目的实体或按钮，结合伙伴视线、姿态、构图和局部亮度。只有当前目标允许一次轻微提示动作。
2. **可选玩法**：稳定图标、正常尺寸、安静展示。宝宝可以主动离开主线，不被反复拉回。
3. **系统功能**：帮助放标题或导航右侧；设置、数据、更新归家长层；返回、休息始终可找到。

颜色与形状共同编码：当前站用暖黄光圈和播放标记；已完成用彩色地标和勾章；未来站用低饱和地标和锁标。不能仅靠灰度区分，更不能让所有入口发光、跳动或挂红点。红点仅表示真实未读信息，不能作为泛化的“来点我”。

地图中的地标同时是入口：树果园代表颜色和食物，小营地代表问候与合作，海岸代表自然观察。点地标开始；不在地标外再堆一套等价卡片菜单。装饰不使用按钮轮廓，按钮不伪装成背景。

**语音提及谁、什么物体，镜头与高亮必须对应那个对象。** 互动时先让伙伴和目标物进入可见区域，再播操作提示。镜头移动不能使手指下的目标突然换位。

## 2. 功能引导：边做边懂

首次接触只教眼前一步。例如第一次投喂：“点树果，递给皮卡丘。”画面同时指向实际树果。成功递出后结束教学，允许宝宝继续探索。

建议区分 `未遇见 → 已展示 → 尝试过 → 成功做过`。它们描述操作经历，不表示英语掌握程度。成功以真实结果事件为准，例如树果实际消费并完成投喂，不能仅凭点击或关掉帮助。

按需要提供帮助：

- 正常状态：清楚的物体、短标签和必要语音足够，不放手指遮挡答案。
- 宝宝主动点帮助：一句具体指令 + 一次操作演示；提示留在当前模块。
- 重复无效点击或明显操作失败：提供“我来帮你”，保留原进度。
- 只是停顿：不直接判定困难；最多温和邀请一次，随后保持安静。
- 成功操作后：撤去箭头、高亮与教学卡，避免熟练用户被重复教学。

教学演示与独立练习分开：练习只指向选项区域；宝宝请求讲解时才展示正确对象，并沿用“辅助完成”记录。语音播放失败、麦克风不可用不能被解释成宝宝不会。

## 3. 四层反馈，各自承担一个作用

| 层次 | 宝宝需要知道 | 推荐表现 | 不应替代的事实 |
|---|---|---|---|
| 按下 | 我点到了 | 控件轻微压下、选中边框；低干扰短音效 | 不提前宣布行为成功 |
| 执行 | 它正在做 | 伙伴看向物体、走近、接取；有可理解的等待状态 | 不能用转圈掩盖无限等待 |
| 结果 | 我做成了什么 | 伙伴吃到果子、球真的传回来、花朵恢复；一句具体回应 | 不把提示下完成称为独立掌握 |
| 成长 | 这件事留下了什么 | 路线点亮、地标变化、小日记留下回忆；能量 toast | 不给一次动作重复发多层奖励 |

先动作回应，再播放一句反馈，再展示必要成长变化。长配音、奖励音效与地图庆祝不得同时争抢注意力。必要的保存失败信息优先于庆祝；只在成功保存后点亮关卡或发奖励。

正反馈措辞具体且温和：“你把树果递给伙伴了”“这次听出了 green”，比每次泛泛说“你真棒”更清楚。尚无独立理解证据时只描述行为，例如“我们一起找到绿色啦”。

答错后的链路：保留场景 → 温和重听 → 可选讲解 → 再尝试。没有刺耳警报、扣心或强迫重做；尝试和求助都不造成伙伴失望。

## 4. 一条可落地的样板：树果野餐

| 环节 | 画面与操作 | 语言与反馈 |
|---|---|---|
| 发现 | 学习地图的树果园是当前站，伙伴站在入口旁 | 一句“和伙伴准备树果点心吧” |
| 学一点 | 清晰呈现 2–3 个物体，直接进入符合当前学习阶段的任务 | 复用现有颜色、食物词汇与讲解；不加无意义前置页 |
| 做出来 | 听辨任务中选择目标，果子实际进入篮子 | 重播目标词；镜头中看见选择带来的变化 |
| 完成 | 伙伴分享点心，课程记录可靠保存后点亮地标 | 一句具体结果反馈 + 能量 toast；“看看下一站”为主动作 |
| 岛上再遇见 | 日后宝宝主动进入野餐时，再遇到同一词句 | 如已存在的 Thank you；参与不强制开口，不再强制答题 |
| 留下痕迹 | 地图保留已完成标记；已有回忆系统可呈现那次分享 | 课程完成、场景参与、独立理解分别记录 |

场景动作可以是低成本的二维物体移动与伙伴动作，不要求每道题新增完整 3D 场景。先证明宝宝理解因果，再扩大制作量。

## 5. 统一注意力与中断规则

优先级：**家长时间限制/阻断性故障 → 当前宝宝动作及录音/教学 → 当前动作结果 → 用户主动帮助 → 可选新邀请 → 氛围事件。**

- 已开始的操作不能被“伙伴饿了”“新礼物”等邀请打断。
- 一次只播放一条前景语音；奖励提示尽量靠近对应动作或资源位置，避开操作区。
- 去其他页面、关面板或换伙伴后，旧任务的镜头、语音和引导立即失效。
- 录音中不播指导；后台不催促；休息时间到达后不展示“再来一关”的主按钮。
- 减弱动态效果时用静态边框、状态标记和清楚文字替代动画；静音时可独立理解动作。
- 宝宝不照顾伙伴时，伙伴能自己生活，不因退出而挨饿或伤心。关系感来自共同经历。

## 6. 实施次序与验收

| 批次 | 范围 | 验收标准 |
|---|---|---|
| A：做通一个闭环 | 树果主题；学习地图→课程→结算→岛上再遇见 | 每步只有一个推荐动作；声音和对象一致；保存失败不假成功；可主动退出并恢复 |
| B：改进引导判断 | 关键操作成功事件、帮助状态；扩展现有提示调度 | 看过不等于做过；不中断录音/动作；错误提示不会无期限排队；熟练后不反复指挥 |
| C：形成统一反馈 | 投喂、种植、玩球、故事等高频路径复用四层反馈规则 | 有按下、执行、完成、失败的可见结果；无双重结算、遮挡和叠播 |
| D：增强阶段成长 | 逐章环境、终点地标、真实经历回忆 | 已完成/当前/未来清楚；回顾独立收纳；成长不依赖连续登录，不增加强制领取步骤 |

先验证网页上的平板横竖屏、手机小屏、深色主题、静音、减弱动态效果和弱网。移动端安装包仍暂停。

邀请家长观察：宝宝第一下点了哪里、是否需要解释、能否发现操作结果、是否顺利找到下一站或休息。建立基线后再比较，不先承诺改善百分比。选择不玩不算失败。

完成率只是可用性线索；英语效果需区分听过、辅助完成、独立理解及换情境应用。无需为此默认采集孩子录音或录像。

## 依据与边界

- [NN/g：Recognition and Recall](https://www.nngroup.com/articles/recognition-and-recall/)：利用可见选项与情境提示减少回忆负担；不是本产品儿童试验结论。
- [NN/g：Visibility of System Status](https://www.nngroup.com/articles/visibility-system-status/)：及时说明系统状态和动作结果。
- [UNICEF：Responsible Innovation in Technology for Children](https://www.unicef.org/innocenti/reports/responsible-innovation-technology-children)：以儿童福祉、能力感、自主与关系体验作为设计参考；不是特定奖励机制的效果保证。

以上为结合项目做出的设计提案，不声称已复刻或实测某款手游的具体机制。不使用连续签到惩罚、限时焦虑、随机付费奖励、伙伴内疚提示来提高留存。

## 一起玩扩展：戳泡泡与一起跳（2026-10-18）

- 主选择区是玩球、戳泡泡、一起跳三个图片入口；歇一歇、喂点心保留为次级操作。完成后可直接换个玩法，保留伙伴，无需先返回岛屿。
- 戳泡泡：伙伴面前出现一个可点击的立体泡泡。点击后泡泡散开、播放轻量 pop 音效，伙伴点头回应；依次听 One / Two / Three，三个泡泡后结束。
- 一起跳：点击伙伴本身或右下角“跳一跳”，伙伴完成一次起跳与落地；每轮听 Jump，三轮后结束。减少动态效果时保留小幅必要动作，取消泡泡漂浮。
- 两种玩法均由宝宝发起每一轮，无作答期限、不自动替宝宝操作。沿用到达检查、后台取消、遮挡暂停、离开清理；只有完整结束才写入一条陪伴回忆。
- 新增两句火山中文操作录音，沿用已存在的英语录音。听完且实际参与才记英语接触及动作，数字使用 count:1–3，使用独立活动上下文，不误点亮玩球课程、不记录为独立答对或开口。
- 玩法依然在既有第一人称互动镜头中进行。泡泡按屏幕边界约束位置，保留 96px 点击区域；标题文字显式采用深色墨色，避免深色主题下浅底白字。
