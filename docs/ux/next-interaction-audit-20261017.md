# 后续交互优化盘点 · 2026-10-17

## 结论与范围

本轮只盘点，没有修改产品代码、配音或发布版本。核对正式版本为 `2026-10-17T05:59:32.129Z`（10/17 13:59）。检查当前源码，并使用隔离测试存档在 1024×768、390×844 浏览器中走查图鉴、回岛、学习、装扮、故事等路径。没有使用孩子的录音，没有调用云端转写，没有修改正式域名上的用户存档。

发现 **8 项可执行优化：P1 3 项，P2 5 项**。这不是全站无遗漏审计或 iPad 真机验收；代码确认的异常分支明确标记，不当作已在设备上复现。

主要方向：**保留孩子刚才的选择，让系统完成中间步骤，操作结果要在画面上看得见。** 自动化不能替孩子消费能量、上传录音，也不能把没听到的内容记成“学过”。

## P1：先补体验断点

### U01 · “回家陪它玩”没有找到它

- 证据：`src/screens/DexDetail.tsx:53` 只跳转 `{name:'home'}`；`src/store.ts:40` 的 home 参数只有 station，没有目标伙伴。
- 浏览器复现：图鉴 → 雷伊布 → 回家陪它玩，回岛后没有雷伊布互动卡片，仍显示皮卡丘的陪伴邀请。
- 影响：按钮承诺“陪它玩”，实际要求孩子再次找伙伴；收集数量增加后更明显。
- 建议：跨页面携带目标伙伴，回岛后一次性选中、切换特写并打开互动卡。捕捉结束的“带它回家”同步沿用这条路径。
- 验收：指定雷伊布返回时，镜头和卡片均对应雷伊布；手动离开后不再反复抢镜头。捕捉路径也需要单独验收。
- 分类：流程连续性；建议 `/harden`。

### U02 · 配音失败时，部分学习环节只能不断重试

- 代码确认：`src/screens/LearningLesson.tsx:70–110`。首次语音失败只显示重试文字；听读、情境听读和认识阶段依赖 `heardTarget/ heard` 才允许前进。认识阶段没有显式跳过；纯听读可切换指认，但不适合用做所有低龄孩子的故障兜底。
- 影响：弱网、尚未缓存或播放失败时，孩子可能反复点喇叭，不能自然继续当前学习方式。
- 建议：有限次数自动重试；失败后给“稍后再听 / 先看下一个”，保留内容待补听。播放失败不记听过、独立答对或已掌握；课程奖励结算也要定义清楚。
- 验收：用实际失败音频请求验证，不是只关闭音量。可继续或退出，不无限加载；恢复后能补听，学习记录不虚增。
- 边界：本轮未注入网络故障，这是源码确认的失败分支。
- 分类：容错与无障碍；建议 `/harden`。

### U03 · 网页日记的能力说明出现得太晚

- 证据：`src/components/GuidedDiary.tsx:55,63,69–80`：网页版跳过云端转写；开始问题页仍主推说一说，直到三个问题后的总结页才说明不支持转写。`src/screens/Diary.tsx:50,56`：故事生成需要非空文字，故事屋入口仍写“我的声音，也能变成故事”。
- 影响：孩子完成录音后才知道需要大人补写，和入口形成的期待不一致。已保存声音不是丢失，但后续成书依赖家长。
- 建议：网页版默认完成为“声音日记”：录完即可拥有可播放的日记卡；文字成书作为家长可选操作。入口即说明能力。具备转写服务的本地版继续保留明确上传动作，不因自动化取消录音上传确认。
- 验收：仅录声音也有完整、可返回、可重听的完成结果；不需要填字才能认为记录成功；前后文案一致。
- 边界：未实际采集或上传录音；依据在线构建开关和 UI 源码。
- 分类：功能预期与完成反馈；建议 `/clarify`、`/distill`。

## P2：下一批降低操作与理解成本

### U04 · 获取能量后，没有接回原来的目标

- 证据：`src/screens/Energy.tsx:30–47` 把换球/升级意图留在 energyGoal，跳往课程和小游戏；`src/screens/LearningLesson.tsx:48–49`、`src/screens/TaskScreen.tsx:82–84` 的结算不读取该意图，只有回岛、故事、下一站等入口。全项目 energyGoal 只由 Energy 页面读取。
- 影响：孩子为了换球来学习，学完仍需自己记住返回换球的路线。
- 建议：结算判断原目标，够了显示“球可以准备啦 / 去升级”，还差时清楚表示差额，并保留自由离开。返回目标不等于自动扣能量；不要强迫再做一组。
- 验收：从缺球/缺升级能量进入，完成后能一键回原目标；普通学习入口保持学习优先；过期目标可取消。
- 分类：跨页流程；建议 `/distill`。

### U05 · 装扮有“摆好”文字，缺少看得见的场景反馈

- 浏览器证据：390×844 的装扮面板几乎占满屏幕，岛屿只剩边缘；截图 `output/qa/ux-opportunities-20261017/decor-mobile.png`。
- 代码：`src/components/IslandRewards.tsx:19–22` 放置后只更新装饰、音效和文字；再点已摆好卡片会直接收起。`:28–32` 的“升级预览”是图标和文字说明，不是真实设施前后对比；`:35` 的看看小岛只关闭面板。
- 影响：孩子难以知道东西出现在哪儿，也可能把再次点击当作“看看”，结果收走装饰。
- 建议：放置后面板缩为小条，镜头温和看向实际摆放点并短时高亮；再次点已摆好项目优先查看，“收起来”放次级操作。升级展示真实前后缩略图或场景预览，仍保留花费确认。
- 验收：点击后能同时看到新装饰和清楚回应；手动拖动立即取消镜头接管；减弱动态效果时使用静态高亮。不能靠增加确认弹窗解决每次点击。
- 分类：响应式与反馈；建议 `/adapt`、`/distill`。

### U06 · 故事自动阅读能力藏得深，而且每本都要重选

- 证据：`src/screens/Stories.tsx:72,96,136–138`。autoPlay 每次打开 Book 初始化为 false；自动翻页在“陪读设置与记录”中。浏览器确认阅读主操作只有上一页、暂停/重听、下一页。
- 影响：想连续听故事的孩子每页都要点；即使家长选过自动模式，下次仍重新设置。
- 建议：提供容易辨认的“听故事 / 一起读”模式，记住家庭偏好；听故事模式普通页面自然翻页，表演/提问页保留停留与跳过。不要默认跳过情绪表达或强迫回答。
- 验收：读一整本无需每页确认；随时暂停和翻回；换故事后偏好保留；互动页不会无限等一个必须答对的答案。
- 分类：自动化与信息层级；建议 `/distill`、`/onboard`。

### U07 · 一起玩选择伙伴时，跨页选中项不容易看见

- 代码确认：`src/components/IslandLivingPanel.tsx:16,39–47`。伙伴每页 3 只，selected 最多保留 2 只；翻页不显示固定已选摘要；点击新伙伴默认加入而不是替换；“喂伙伴”始终用 selected[0]。
- 影响：翻页后孩子可能以为刚点的就是要喂的伙伴，实际仍喂第一页默认选中的伙伴。大量伙伴也要连续翻很多页。
- 建议：固定显示当前伙伴头像；默认单选替换，第二位作为明确的“再叫一个朋友”。喂伙伴按钮使用头像或名字显示实际对象，复用现有找伙伴组件。
- 验收：拥有 4 只以上时，选择后页伙伴再点喂伙伴，目标一致；双伙伴玩法清楚展示两位对象，不产生隐藏选中项。
- 边界：逻辑由代码确认，本轮未执行喂错对象的消费流程。
- 分类：选择状态与可发现性；建议 `/clarify`、`/distill`。

### U08 · 操作感谢与当前需求共享位置，旧感谢可能压住新需求

- 代码确认：`src/screens/Home.tsx:103,308,347,374,579`。careThanks 没有过期时间；同一伙伴存在感谢文字时始终优先于 selNeed，直到重新选伙伴、打开果篮等动作清除。
- 影响：保持卡片打开时，“吃饱啦，谢谢你”可一直占据需求区，后来的陪伴需求不能及时表达。
- 建议：将操作结果设为短时反馈，到时恢复当前真实需求；屏幕阅读器只播报一次，不重复闪动。不能为恢复需求打断正在进行的语音。
- 验收：一次投喂后先看到感谢，随后恢复当前状态；模拟之后出现新需求，需求可见；连续点击不堆叠多条提示。
- 边界：本轮确认状态优先级，无长时间真机驻留复现。
- 分类：状态反馈与弹层生命周期；建议 `/harden`。

## 技术与视觉抽查

局部审计参考分 **13/20**：可访问性 3、性能 2、响应式 3、主题一致性 3、信息/视觉反模式 2。此分只用于本轮样本排序，不代表 WCAG 合规或全站性能评分；未测真实设备帧率、全站对比度与屏幕阅读器。

- 可访问性/响应式：本轮装扮与故事页抽查的可见按钮、summary 没有小于 44px 的命中目标。装扮关闭入口保持可达；主要问题是面板遮住操作成果，而不是按钮过小。
- 性能：当前在线构建中入口 JS 约 1.09 MB、场景 JS 约 1.47 MB（本地 gzip 约 307 KB / 488 KB）。App 静态引入多个页面；可后续按路由拆分。但没有本轮弱网或真机性能数据，不以包大小推断一定卡顿。
- 主题：本轮白天样本延续海岛色板和纸张面板；没有重新验证夜间全部页面，不列未经确认的深色模式缺陷。
- 视觉反模式：定制图标与岛屿场景有辨识度，不需要整体换皮。局部装扮依然是长卡片列表、卡片内文字状态多，挤掉实际场景；这是需要改的具体模式。

## 保留已奏效的设计

- 常用投喂与摸摸已一步完成，野餐到位自动分享，伙伴自动完成玩球回合。
- 前台面板互斥和单一提示位已经建立，继续复用，不另加浮层系统。
- 主线学习已提供能量反馈，进度和帮助进入顶部栏，伙伴画面已缩小；不重复列为待修复项。
- 不强迫开口/书写，学习记录区分听过与独立表现；自动化不能破坏这条边界。
- 资源加载已只预热少数首页伙伴，不能仅凭旧注释误报为全量图鉴解码。
