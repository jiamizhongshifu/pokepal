# Pokopia 同人小镇与主角评估

日期：2026-10-15。对象：`LerSent001/pokepia-town` 提交 `9caddf85107a3b8cd543d0f36de8181bc9b431ce` 的 `town.glb`、`player.glb` 及配套 Blender 源码。它们是同人重建，不是 Pokopia 原版提取资源。

## 结论

**小镇作为美术参考和物件改造来源值得采用；整图直接替换不建议。主角保留为候选，不建议直接接入正式版本。**

这次已经实际渲染，不再仅依据文件名或作者说明判断。文件可在当前项目 Three.js r169 上读取，主角待机和行走可以播放。主要问题是几何复杂度、按材质合并的组织方式，以及幼儿交互尺度。

| 对象 | 判断 | 原因 |
|---|---|---|
| 小镇造型、房屋、花园、圆树 | 可采用方向 | 层次和主题清楚，圆润轮廓适合温和家园氛围 |
| 原始整镇 GLB | 不直接替换 | 637,173 三角面；38 个按材质合并的网格；不包含独立家具交互定义 |
| Blender 场景源码 | 优先采用 | 可以从生成源头输出独立树、长椅、花坛、围栏和桥，保留语义与锚点 |
| 主角 GLB | 有条件保留 | 71,600 三角面、11 材质；只有待机和行走；当前产品没有必须引入可控人类主角的需求 |
| 同仓库普通宝可梦 | 本轮不替换 | 来源是通用 Pokemon-3D-api，而非 Pokopia；本轮没有对这些模型进行视觉评估 |

## 渲染与动画检查

- 使用项目现有 `three@0.169.0`、本地 Draco 解码器、Neutral tone mapping、DPR 1.25，在独立评估页加载真实模型；不启动外部项目代码。
- 通过 1200×900、768×1024、390×844 三种浏览器窗口检查。小镇均可渲染；主角在 1200×900 下检查正面、背面、待机和行走。
- 每组取稳定后的 180 帧：本机桌面 Chrome 约 60 FPS，帧间隔 P95 约 16.7–16.8 ms；最终页脚本错误列表为空。
- 这是独立资产场景，没有叠加正式游戏 UI、20 只宝可梦、音频和后处理；测量是浏览器帧间隔，不是 GPU 计时。draw calls 来自 `renderer.info.render`，不作为所有阴影通道的总成本。
- 检查动画 0%、25%、50%、75%、100% 时刻的包围盒，未出现非有限坐标或明显骨骼炸裂。行走采样中脚底最低约 -0.033，后续接入需要校准地面高度。
- 只验证了待机/行走，不包含浇水、种植、拿取、坐下、表情切换或角色导航验收。
- 初版统一阴影范围造成明显条纹；评估页按模型大小调整阴影范围与偏移后改善。原始问题属于测试灯光适配，不能直接归因为损坏模型。最终主角脸部仍有较硬阴影，正式设计应单独调整角色照明。

**尚未验证 iPad Safari、热降频、耗电、低端设备、离线安装、正式场景整合或真实儿童使用。** 浏览器竖屏窗口不等于移动设备性能测试。

## 视觉与 3–6 岁适配

以下是基于本轮实际截图的设计判断：

1. **有价值的部分：** 圆树冠、低矮房屋、桥、花坛的组合容易识别；花园与河流提供自然分区，适合轻量照料互动。
2. **画面密度：** 小花、石砖和围栏同时出现时细节较密；390 像素宽的整镇预览里家具明显过小。儿童主界面应聚焦一个花园/一个院子，使用明确的大点击目标。
3. **色彩：** 原样本草地偏高饱和黄绿，容易抢走伙伴与任务提示的注意力；建议降低背景饱和度，将强调色留给可操作对象。此判断针对本轮中性评估灯光下的 GLB，不声称复现了原作者整套渲染。
4. **主角表情：** 大头比例易辨认，但眼睛小、嘴形固定，温暖的回应不足；不能把有行走动画等同于能完成儿童情绪反馈。
5. **玩法复杂度：** 源项目的道路、桥和高差导航是参考实现，不能直接套在现有岛屿上。3–4 岁适合点目标后自动完成移动；5–6 岁才逐步加入摆放选择。

## 当前项目接入差异

- `src/scene/modelUtil.ts` 当前禁用 Draco。应离线解压并导出无压缩样本，或增加随离线包提供的本地解码器，再测缓存；不能依赖外网 CDN。
- 原始 `town.glb` 的 mesh 名是材质名。直接点击树叶网格不能知道点中了哪一棵树。推荐修改生成脚本，在导出前按物件保留节点、ID、碰撞体和交互锚点。
- 当前 `layout.ts`、`zones.ts`、`hq/Terrain.tsx` 的坐标和障碍定义不同。整体缩放新城镇不会自动解决穿模、落地高度和宝可梦活动区域。
- 场景的水只是 GLB 几何/材质；本轮预览没有引入原作者的 Water2、泡沫、导航和镜头控制。下载模型不等于获得完整互动场景效果。
- 当前材质归一化会更改透明与面朝向设置，不能不经审查套用到所有新场景物件。
- 当前单文件预缓存上限为 8 MiB；原始 GLB 虽在限制内，离线解压后的文件大小仍需重新检查。

## 建议的下一步范围

选择 **“拆物件试点”**，继续使用当前已验收的宝可梦资源与幼儿 UI：

1. 从源码选出树、长椅、花坛、围栏、桥和小屋，生成独立模型；保留作者与许可记录。
2. 先做单个小花园，目标为 8–15 万三角面以内；这一数值是初始工程预算，不是保证 iPad 流畅的阈值。
3. 重复树与花使用实例化；石墙细节改用更低细分几何或贴图。若保留主角，先降至约 1–1.5 万面、2–4 材质，并重验动画。
4. 绑定一个“点击花苗 → 杰尼龟浇水 → 开花”的互动，以及返回/取消。场景里只突出一个操作目标。
5. 在正式渲染配置和真实 iPad 上检查触控、帧率、发热和离线，再决定是否扩大替换范围。

这是后续实施建议，本轮没有执行上述改造，也没有改变正式场景、模型清单或存档。
