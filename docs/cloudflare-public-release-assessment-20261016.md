# Cloudflare 公开网页版性能评估

评估日期：2026-10-16。用户覆盖：中国大陆与海外。基线：已发布本地构建 `2026-10-16T10:23:43.808Z`（18:23）。本轮只评估，未修改应用代码、云端配置或执行部署。

## 结论

Cloudflare 可以承担网页入口和静态资源分发。现有项目应先拆出按需加载的“在线体验版”，不宜直接上传家庭离线安装版。主要瓶颈是全量后台下载、语音分包更新放大、设备端 3D 渲染和大陆访问线路；不是需要给每位用户分配一台游戏服务器。

目前可以确认“具备改造成公开网页版的技术基础”，不能确认“当前版本面向大陆与海外均可直接流畅上线”。本轮没有 Cloudflare 部署地址，因此没有海外/大陆运营商真实链路、并发压测或移动真机 FPS 结果。

## 实测体积与加载行为

GB/MB 使用十进制，MiB 使用 1024² 字节。

| 项目 | 当前结果 | 影响 |
|---|---:|---|
| 本机 dist 目录 | 60,021 个文件，4.89 GB | 含历史 chunks、旧语音包和单条 MP3；不等于每个用户下载量，不应原样上传 |
| 依照当前资源清单保留的候选集合 | 约 58,057 文件、1.98 GB | 仍同时含单条 MP3 和离线包；这是清单推导值，不是构建过的精简网页版 |
| 核心预缓存 | 1,737 项，347.68 MB / 331.57 MiB | 包含全图鉴、模型、故事和索引；不是仅首屏必要资源 |
| 全量离线语音包 | 256 包，816.37 MB / 778.55 MiB | 56,061 条语音，不适合陌生访客首次进入就全部安装 |
| 完整离线安装逻辑资源量 | 1.164 GB / 1,110.12 MiB | 不含缓存元数据、运行内存、旧版本重叠及压缩传输差异 |
| 欢迎页浏览器资源 | 24 个页面资源，编码正文合计约 5.17 MB | 不含 Service Worker 自己发出的后台下载 |
| 欢迎插画 PNG | 2.31 MB | 可生成 WebP/AVIF 派生图并提供适配尺寸 |
| 配音总 manifest | 原文 3.23 MB，gzip 约 0.90 MB | 模块初始化立即请求；打开首页就加载所有台词映射 |
| 主 JS / 3D JS | 原文 1.01 / 1.46 MB，gzip 0.28 / 0.48 MB | 3D 已分包；相较图像和全量配音不是首要体积瓶颈 |
| 最近一版 50 条新增配音 | 46 个新包、148.01 MB | 按文件哈希前缀分组，少量新增导致多个大包重新下载 |
| 单文件限制检查 | 无文件超过 25 MiB | 当前真正的托管硬限制主要是文件总数，不是单文件大小 |

按当前离线逻辑资源量直接除以持续带宽：10 Mbps 约 15.5 分钟、30 Mbps 约 5.2 分钟、100 Mbps 约 1.6 分钟。这是字节预算的传输估算，不是页面首屏实测；压缩会减少部分传输，延迟、丢包、请求调度和写缓存又会增加时间。

**页面不需要等 1.16 GB 全部完成才能进入。问题是全量安装会在后台抢带宽、耗电和占缓存，并使 Service Worker 安装完成依赖全量资源。**

生产构建 `dist/registerSW.js` 在 window load 后自动注册。`vite.config.ts:47` 使用宽泛资源预缓存；`public/voice-cache-sw.js:130` 在 install 事件调用全量配音安装。新建隔离浏览器仅访问欢迎页及空岛，实际已看到 1,737 项 core 缓存和 257 项 voice 缓存（256 包 + 索引）。未手动要求下载全量离线包。

空岛进入后观察到约 9.04 MB 的额外资源正文，包括场景 JS、8 个场景模型、HDR 和贴图；该阶段已命中 Service Worker，不能把这次局域网耗时当成公网冷启动速度。

证据：`output/qa/cloudflare-readiness-20261016/inventory.json`、`cold-welcome.json`、`home-network.json`、`voice-update-amplification.json`。

## 设备端 3D 风险

有利基础：Three.js 场景已延迟加载；退出家园会停止绘制；有 1.25 → 1 → 0.8 分辨率与阴影/草地降级；首页只预热 5 位角色的图片；语音解码缓存上限 120 条。

尚待处理：

1. `src/scene/HomeScene.tsx:129` 对所有 captures 建立 Resident，没有同屏活跃数量上限。每只都有模型、动画、活动逻辑和避让。`src/scene/crowdMotion.ts` 多处扫描伙伴集合，人数增加时 CPU 开销也增长。
2. 阴影、草木、装饰及场景基础绘制仍重。低画质下仍保留离屏渲染和四角模糊，不能仅靠降低 DPR 解决所有开销。
3. 模型/纹理加载缓存和隐藏家园保留有利于返回页面时状态连续，但内存不会等于当前画面上的对象数。需要预算与可回收策略，且不能破坏之前修复的活动续接。

本机 Chrome、Apple M2、开发构建、1024×768、关闭高画质灯光的 4 秒诊断样本如下；三个有效采样均为自动降级后的 DPR 0.8，顺序为 30 → 10 → 0，同一会话复用资源缓存。统计覆盖阴影/主场景/后处理，不使用最后一个全屏 quad 的错误计数。

| 实际 Resident 数 | 每帧绘制调用范围 | 三角形提交量范围 | rAF 间隔中位 / P95 |
|---:|---:|---:|---:|
| 0 | 709 | 108 万 | 16.6 / 18.7 ms |
| 10 | 791–910 | 120–127 万 | 16.4 / 22.9 ms |
| 30 | 1,085–1,093 | 150–151 万 | 18.5 / 25.2 ms |

这些是本机短样本诊断，不代表手机、iPad、长期发热后的表现，也没有证明 151/388 只同屏能流畅运行。rAF 间隔不是 GPU 专用计时。正式发布需增加中低端安卓与实际 iPad 的持续测试。

建议先以 8–12 只同时活跃作为待验证的低配起点：其他收藏仍完整保留，可快捷召回、轮换入场；远处降低动画/逻辑更新频率、使用更低细节；继续减少重复材质和绘制调用，低配允许关闭阴影/模糊。不能直接删除收藏或重置活动状态来省性能。

证据：`scene-0.json`、`scene-10.json`、`scene-30.json`、`scene-metrics.js`。

## Cloudflare 能解决什么

Pages 免费方案最多 20,000 文件，付费方案可到 100,000，单文件上限 25 MiB。当前目录超出免费文件数，但并非 Cloudflare 所有方案都无法承载；只升级方案也不会解决用户下载和设备开销。[Cloudflare Pages 限制](https://developers.cloudflare.com/pages/platform/limits/)

推荐：

- 应用 HTML、CSS、JS 和少量启动资源放 Workers Static Assets 或 Pages。
- 大量角色模型、图片、录音放 R2，使用资源自定义域名和正确的缓存规则；不要使用有速率限制、仅面向开发的 r2.dev 作为生产资源地址。[R2 公共访问与缓存](https://developers.cloudflare.com/r2/buckets/public-buckets/)
- 静态资源优先走 CDN，不让每次模型/图片请求都经过计费 Worker。Workers Static Assets 静态请求免费且不限量，Worker 执行另计；错误设置 run_worker_first 可能让静态请求也受 Worker 配额影响。[静态资源计费说明](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/)
- 录音与模型使用内容哈希和长期 immutable 缓存；入口 HTML/版本清单采用可更新策略。引入独立资源域名时需要同步改资源基址、CORS、Service Worker 缓存与离线资源校验，不能只上传 R2 后替换一个域名。

R2 Standard 当前标价：$0.015/GB-month，Class B $0.36/百万次，互联网出站流量免费；每月含 10 GB-month 存储、100 万次 Class A、1,000 万次 Class B 免费额度。最终费用取决于 CDN 命中、请求量、Worker/API 调用，不能承诺整个应用永久免费。规模初期更值得关注体验与云端语音识别费用，而不是几 GB 静态存储。[R2 价格](https://developers.cloudflare.com/r2/pricing/)

### 大陆与海外

普通全球 Cloudflare 方案不能视为已提供中国大陆节点服务。China Network 是 Enterprise 的独立订阅，并且支持的产品范围另有约束；不能推断 Pages/Workers/R2 会自动全部落在大陆节点。[China Network 官方说明](https://developers.cloudflare.com/china-network/)

- 海外：优先 Cloudflare 静态入口 + R2 自定义资源域名。
- 大陆：保留同一套前端构建，规划可替换的国内对象存储/CDN 源；至少大资源需要可区域分发。若实际测试显示 HTML/JS 本身也不稳定，入口也需国内分发，不是只换图片域名。
- 稳定产品域名尽量保持一致：当前存档在本机 IndexedDB，变更网页 origin 不会自动带来原 iPad 存档，需要导入/迁移。
- 发布前在大陆电信/联通/移动及目标海外地区实测 DNS、TLS、TTFB、资源错误率、进入岛屿时间。当前无此类测量，不给出虚构延迟或可用性保证。

## 不随静态部署迁移的功能

语音日记转写目前是 `scripts/mobile/diary-api.mjs:5` 在本机启动 Python 子进程，读取本机火山凭据。上传 dist 到 Pages 不会带上这个后端。需要改成独立线上 API/Worker 与火山服务通信，或首版明确保留本地录音/家长文字输入、暂不开放云转写。

公开 API 需要把当前局域网内存限流改为可持续的配额、幂等和并发控制；Origin 检查不能当身份授权。不能把现有火山账号密钥打包到前端。公开日记录音上传仍应由家长明确选择，并说明去向；本次没有调用语音识别或上传任何儿童录音。

已有预生成的教学配音只需静态分发，不应改成每次播放实时付费生成。

另：项目 README 当前明确定位家庭内部测试；游戏提取模型与角色素材的公开分发授权未在本轮确认。这是公开发行前的独立事项，性能评估不能替代素材授权核对。

## 建议执行顺序与验收目标

以下是拟定预算，不是已经达到的性能数据。

| 阶段 | 要做的事 | 验收目标 |
|---|---|---|
| P0 在线与离线分离 | 单独 online 构建；默认只缓存应用壳；角色、故事、录音按需加载；全量离线由家长主动选择 | 新访客不自动下载完整模型和 256 个语音包；旧离线版继续可用 |
| P0 发布资源治理 | 独立干净输出；移除历史包与旧 chunks；按需音频清单；哈希单条或课程小包 | 50 条录音新增不再造成 148 MB 更新；只上传白名单发布产物 |
| P1 首次体验 | 首页插画提供现代格式和适配尺寸；当前故事/课程小索引；优先首位伙伴与当前场景 | 欢迎页传输目标 ≤2 MB；首个可玩场景累计目标 ≤15–20 MB；10 Mbps/100 ms 条件下以实测优化到 ≤10–15 秒 |
| P1 场景预算 | 活跃伙伴上限、远近细节、减少绘制、可选关闭高成本效果 | 低端目标 ≥30 FPS；中端目标 ≥50 FPS；连续体验 15 分钟无明显发热降速/闪退 |
| P1 区域网络 | 海外 Cloudflare + R2；大陆可替换资源/入口分发；同域存档策略 | 两区域真实网络下首屏与语音成功率达标；不能用本机 localhost 验收替代 |
| P1 线上 API | 转写迁移或明确暂缓；服务端密钥、限流、费用上限与失败反馈 | 同时录音转写场景可控，不向浏览器暴露凭据 |
| P2 小范围试运行 | 新访客、慢网、缓存二次进入、版本更新、中断恢复 | 再根据设备/区域数据决定公开扩量；性能记录不采集儿童原声或日记正文 |

建议先完成 P0，再进行带真实资源的小范围 Cloudflare 体验测试，随后完成 P1 的设备与区域验收。没有必要先为了静态并发购买昂贵计算服务器。
