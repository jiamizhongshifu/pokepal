## P1 · 场景寻路断连，互动目标被移到设施之外

**位置：** `src/scene/navigation.ts:7`、`src/scene/islandLife.ts:54`、`src/scene/Resident.tsx:337`；失败用例 `scripts/tests/island-child-flow.test.ts:16`。

**证据：** 扩建 2 级、半径 0.6，从 `(-2, 0)` 到 `(-2, -18)`，目标 `clearSpot=true`，但路径终点是 `(-4.05, -5.30)`。换起点后，有的能到达、有的仍停在中部，因此不能描述为“整个扩建区域都不可达”，而是导航连通分量被切开。见 `navigation-probe.json` 与 `navigation-starts.json`。

更直接的业务影响：初始化 STATIONS 时，把每个设施原目标覆盖为从固定起点 `(0,4)` 得到的路径终点，没有限制偏移距离。当前默认布局有 **27 个非水中互动目标距设施中心超过 4 单位**：音乐舞台约 4.31，部分树果约 5.01，睡垫最高约 6.75，树荫最高约 8.02。场景代码约定 1 单位约 1 米。并非每个偏移都必然可见错误，但这些距离已远超多数设施本身尺寸。

**影响：** 伙伴可能在远离睡垫、树果或舞台的位置被判为“到达”；扩建与前往互动的反馈不可信。`Resident` 的到达判定使用已经被改写的目标，所以单纯检查到达回调不能发现问题。

**建议：** 梳理树冠/树干/设施碰撞与通道宽度；为设施保留原始锚点和有限范围的接近点。不可达时显式返回未到达，不能无限远重定位并算成功。装饰与扩建改变后重算有效接近点，覆盖多种体型与起点。

**验收：** 失败测试恢复；所有主要设施从常用出生点可达，接近点距设施在各自允许范围内；不可达不触发互动完成。不要通过放宽测试阈值掩盖断路。

## P1 · 新声音日记缺少完整备份路径

**位置：** `src/screens/Parent.tsx:53`、`:177`，`src/screens/Diary.tsx:14`、`:45`、`:47`，`src/components/GuidedDiary.tsx:11`，`src/lib/db.ts:16`。

**证据：** 家长导出只序列化 SaveData，明确不含 `diaries` / `recordings`，并要求去日记页另存原声；但默认的新日记为 `guided:true`，分问题的 `DiaryRecordings` 只有原生 audio 播放控件。应用的“下载原声”链接仅在旧版非引导式分支。合成引导日记页面实测 1 个 audio、0 个 `a[download]`，展开家长操作也无显式原声导出。

**影响：** 家长按指引备份存档后，仍不能通过明确、统一的产品入口保全新日记原声；换设备或清除站点数据后，存档文件不能恢复日记。浏览器媒体菜单可能提供下载，但不能替代 iPad 等平台一致的备份流程。未发生或模拟删除真实数据。

**建议：** 提供包含每个问题音频、文本、标题和日期的日记导出/导入；家长备份入口清楚列出包含项，录音保存失败时也应有可用的应急下载。

**验收：** 新旧日记、仅声音日记、已生成故事分别导出，在干净测试来源导入后能读文字、播放每段声音，失败过程不覆盖原记录。

## P2 · 复习配音失败后缺少“稍后补听”的可执行动作

**位置：** `src/screens/LearningNotebook.tsx:57`、`src/screens/LearningLesson.tsx:108`。

**证据：** `LearningRound` 在 audioFailed 时禁止自动推进；其 fallback 需要 onSkip。主线传入 onSkip，但 LearningReview 没有。浏览器阻断 `*voice*` 请求后，页面显示“这段声音可以稍后补听”，点击正确选项后仍停在第 1 题，答案禁用，没有继续或暂存退出动作。见 `review-audio-failure.txt/png`。

**影响：** 网络不稳的宝宝只能反复点重听或返回，文案承诺的“稍后”没有对应操作。返回仍可用，因此不是整个应用锁死。

**建议：** 复习也采用待补听队列，允许跳过当前不可用声音或保存这组进度后退出；未听到的题不要记成独立掌握或虚发完成奖励。

**验收：** 声音请求失败、超时、恢复网络都能有明确去路，补听不重复奖励。

## P2 · 发布流程没有把业务回归设为门禁

**位置：** `package.json:6`、`scripts/online/build.mjs:7`、`scripts/tests/island-child-flow.test.ts:11`。

**证据：** 在线构建调用 prepare、tsc、vite，没有执行业务测试；普通 build 同样不运行测试，package.json 没有统一 test 脚本。本轮已有 1 项失败，但类型检查仍通过。此外，部分测试夹具直接依赖 `output/qa/island-living-20261016/test-save.json`，测试可移植性依赖历史输出目录。当前目录不是 Git 工作树。

**影响：** “能构建”不足以证明奖励、导航、保存等业务正常；源码和发布版本对应关系依赖手工记录。现有构建会保留上一版资源，这是优点，但不能替代源代码版本与回归门禁。

**建议：** 固定业务测试入口和 fixtures；发布前必须通过测试、类型检查、必要 UI 冒烟。建立源码版本与 release id 对应关系，保留回滚路径。无须为小改动全面重构。

**验收：** 人为令关键业务测试失败时构建发布流程停止；干净环境可复跑；能从 release id 定位精确源码与验证记录。

## P2 · 首包与存档更新存在性能扩展风险

**位置：** `src/App.tsx:1`、`:39`，`src/screens/Home.tsx:50`，`src/store.ts:204`、`:369`。

**证据：** 大部分页面静态导入，HomeScene 已拆包。当前在线发布主 JS 为 1,114,690 字节（本地 gzip 316,395），HomeScene 1,473,013（gzip 488,197）。这些是构建文件测量，不是网络实测传输量。每次 mut 都 structuredClone 全存档、替换 save，App/Home 订阅整个 save；家园护理每 10 秒更新。随捕获、学习记录增长，克隆与渲染成本会上升。

总资源目录约 1.18 GB，其中配音约 819 MB，已按包按需加载，**不能把总资源量当作首屏下载量**。

**建议：** 先测低端安卓/iPad冷启动、长期存档、进入/离开家园；按数据决定页面拆包、细化 store selector 和状态更新范围。避免未经测量重写全部状态层。

**验收：** 留下同设备/同网络前后对比的首屏、可交互时间、长任务、内存与帧率证据。本轮未证明现有设备必然卡顿。
