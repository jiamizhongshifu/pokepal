# 交接文档：宝可梦 3D 模型、动作与叫声素材的交付和接入

本文档给负责准备素材的一方使用。它规定了 PokéPal 能直接接入的素材格式、目录、命名和验收方式。

本文档**不包含**任何素材获取方法（下载、解包、解密等）。素材从哪里来、是否有权使用，由素材提供方自行判断并负责。

## 1. 项目背景

PokéPal 是一个给 4 岁孩子用的宝可梦中英双语互动游戏，家庭自用、不公开部署。

- 技术栈：Vite 6 + React 18 + TypeScript 的离线 PWA，3D 家园用 React Three Fiber 8 + three.js 0.169。
- 运行设备：iPad（Safari / 添加到主屏幕），完全离线。
- 宝可梦现在在 3D 家园里是“立绘立牌”（面向镜头的 2D 图片）。只要某只宝可梦有了 3D 模型，家园会自动用模型替换立牌，其余没模型的继续用立牌，可以逐只替换。
- 项目根目录：`/path/to/pokepal`

## 3. 3D 模型交付规范

### 3.1 目录和命名

```
models-src/
  25/
    pikachu.glb          ← 模型文件，文件名随意
    pikachu_body.png     ← 贴图放在同一个文件夹（GLB 内嵌贴图则不需要）
  1/
    bulbasaur.fbx
    textures/...
```

- 每只宝可梦一个文件夹，**文件夹名就是全国图鉴编号**（纯数字，不补零）。
- 每个文件夹只放一个模型文件。支持格式优先级：`.glb` > `.gltf` > `.fbx` > `.dae` > `.obj`（同一文件夹有多个时取优先级最高的）。
- 贴图用 PNG 或 JPG，和模型文件放在同一个文件夹，相对路径能被模型正确引用。

### 3.2 模型要求

| 项目 | 要求 |
|---|---|
| 坐标 | Y 轴朝上；脚底大致在原点附近（会自动贴地，不必精确） |
| 朝向 | 正面朝 +Z 最好；朝向不对时可以在清单里用 `rot` 修正，不必改模型 |
| 比例 | 任意。系统会按宝可梦真实身高统一缩放 |
| 面数 | 建议 ≤ 8000 三角面；超出会自动减面（骨骼权重保留），但可能影响细节 |
| 贴图 | 单张建议 ≤ 1024×1024 |
| 骨骼 | 带骨骼的蒙皮模型；静止姿态（bind pose）如果是 T 姿势或塌缩，需在清单里指定 `pose` |
| 体积 | 转换后单只 GLB 建议 ≤ 1.5 MB（整个离线包要控制在 iPad 能流畅安装的范围内） |

### 3.3 动作要求

家园里只用两种循环动作：**待机**和**走路**。动作名按下面的关键词自动识别，不区分大小写：

| 用途 | 动作名应包含 | 例子 |
|---|---|---|
| 待机（必需） | `idle`、`wait`、`breath`，或 `defaultwait01_loop` | `idle_loop`、`wait01` |
| 走路（可选） | `walk` 或 `run`（不含 `run_away`） | `walk_loop`、`run` |

以下关键词的动作**不会**被当作待机或走路：`fight`、`attack`、`damage`、`down`、`dizzy`、`faint`、`impact`、`battle`、`turn`、`sleep_end`、`jump`。

- 待机和走路都要是可无缝循环的动作。
- 动作名不符合规则时，可以在清单里用 `idle`、`walk` 字段直接指定动作名。
- 飞行宝可梦（6、12、16、17、18、149、151 等）的“待机”最好是空中扑翼的循环动作。
- 水中宝可梦（116、117、120、121、129、130、131、134、147、148、230 等）的“待机”最好是游动或漂浮的循环动作。

## 4. 叫声音频交付规范（可选）

项目已经有 PokéAPI 提供的叫声，只有在想替换时才需要交付。

| 项目 | 要求 |
|---|---|
| 路径 | `public/pokemon/cry/<编号>.m4a`（直接覆盖同名文件） |
| 格式 | AAC（m4a），单声道，64 kbps |
| 时长 | 0.5–3 秒为宜 |
| 响度 | 建议标准化到约 -16 LUFS，和现有配音音量一致 |

转换参考（从任意音频转为项目格式）：

```bash
ffmpeg -i 输入文件 -ac 1 -c:a aac -b:a 64k -af loudnorm=I=-16:TP=-1.5 public/pokemon/cry/25.m4a
```

旁白和台词配音不需要交付：它们由火山引擎语音合成在构建期生成（`scripts/voice/`）。

## 5. 接入步骤

```bash
cd /path/to/pokepal
npm run models
```

脚本会自动完成：

1. 读取 `models-src/<编号>/` 里的模型；
2. 超过 8000 三角面时自动减面，保留骨骼和动画；
3. 导出到 `public/models/pokemon/<编号>.glb`；
4. 登记到 `src/data/pokemonModels.json`。

单独调整面数预算：

```bash
/Applications/Blender.app/Contents/MacOS/Blender -b -P scripts/convert-models.py -- models-src --faces 6000
```

### 5.1 清单字段（`src/data/pokemonModels.json`）

脚本会生成 `{ "25": { "file": "25.glb" } }`。需要修正时手动补充字段：

```json
{
  "25": { "file": "25.glb", "rot": [0, 180, 0], "scale": 1.0, "idle": "Idle_Loop", "walk": "Walk_Loop" },
  "6":  { "file": "6.glb", "pose": "Fly_Idle" }
}
```

| 字段 | 作用 |
|---|---|
| `rot` | 绕 X/Y/Z 轴旋转（度），修正朝向 |
| `scale` | 在自动缩放的基础上再乘一个系数 |
| `idle` / `walk` | 直接指定待机 / 走路动作名 |
| `pose` | 静止姿态有问题时，定格在这个动作的第一帧作为站姿 |

## 6. 验收标准

每只宝可梦接入后检查：

- [ ] 家园里显示为 3D 模型，大小和同伴协调（皮卡丘约 0.75 米，卡比兽约 1.8 米）。
- [ ] 脚底贴地，不悬空、不陷进地里。
- [ ] 待机动作自然循环，走动时切换到走路动作，没有抽搐或 T 姿势。
- [ ] 贴图完整，没有全黑、全白或错位。
- [ ] 点击模型能打开资料卡。
- [ ] 本机预览帧率不明显下降（同屏 20 只以上时仍流畅）。

先做 3 只做对比截图（建议 25 皮卡丘、1 妙蛙种子、6 喷火龙），交给家长确认效果满意后，再批量处理其余的。之前试过一批社区模型，家长认为效果不理想，所以对比确认这一步不能省。

## 7. 注意事项

- 素材只用于本项目的家庭自用版本，不要提交到公开仓库，也不要部署到公网。
- `models-src/` 是原始素材目录，不要放进 `public/`。
- 不要修改 `src/scene/`、`src/data/behaviors.ts` 等游戏逻辑代码。接入只需要放文件、运行脚本、按需编辑 `pokemonModels.json`。
- 有问题时，把转换脚本的输出和对比截图一起反馈，不要直接删除已有的模型文件。
