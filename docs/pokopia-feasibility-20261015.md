# Pokopia 资源接入核查

核查日期：2026-10-15。范围：用户提供的 d2r-mobile 仓库、Pokopia 官方资料、公开格式工具与当前项目源码。

## 结论与当前状态

Pokopia 的慢生活、共同建设家园方向适合作为本项目的玩法参考；但 **d2r-mobile 不能直接完成 Pokopia 的资源提取或 Web 移植**。资源接入路线可以设计，真实提取目前尚未开始。

- 用户已确认：目前没有 Pokopia 游戏备份、解包目录或导出模型。
- 本轮未取得 Pokopia 模型、贴图、骨骼、动画或场景文件；未知其实际文件结构和版本。
- 本轮公开检索未找到明确验证 Pokopia 模型、动画和场景导出的工具。这个结果不等于证明工具不存在。
- 已读取并保存 d2r-mobile 的相关源码，没有运行其解包、二进制修改、安装或构建脚本。
- 当前项目模型清单有 157 项，所指 GLB 文件全部存在，初代 1–151 编号无缺失。本轮未覆盖这些资源，也未改动运行代码、存档或配音。

## 为什么不能套用 d2r-mobile

核查版本：[`b94670c795e28742abe1a9cadd64a234a77260ab`](https://github.com/jhaizhou-ops/d2r-mobile/tree/b94670c795e28742abe1a9cadd64a234a77260ab)。

| 层次 | 仓库的实际工作 | 与本项目的差异 |
|---|---|---|
| 平台 | 将特定 Switch 游戏的 ARM64 程序交给 Apple 宿主执行，并适配平台服务 | 当前项目是 React / Three.js Web PWA，不能加载这套原生程序 |
| 图形 | 在 Metal 上实现对应图形接口，离线处理原游戏着色器 | 浏览器需要自己的材质、动画和场景渲染；不能直接使用 Metal 路线 |
| 解包 | `extract_game.sh` 提取 ExeFS / RomFS，校验 D2R 指定版本及数据文件 | 提取文件系统不等于导出可用 GLB、贴图和骨骼 |
| 版本耦合 | `patch_nso.py` 含游戏构建 ID、指令偏移和专用规则 | 不能通过换游戏名或目录将这些规则用于 Pokopia |
| 内容 | 仓库不提供游戏模型等原始内容 | 克隆仓库不会得到 Pokopia 资源 |

代码证据：[`extract_game.sh`](https://github.com/jhaizhou-ops/d2r-mobile/blob/b94670c795e28742abe1a9cadd64a234a77260ab/dm/tools/extract_game.sh)、[`patch_nso.py`](https://github.com/jhaizhou-ops/d2r-mobile/blob/b94670c795e28742abe1a9cadd64a234a77260ab/dm/tools/patch_nso.py)、[`DERIVED.md`](https://github.com/jhaizhou-ops/d2r-mobile/blob/b94670c795e28742abe1a9cadd64a234a77260ab/docs/DERIVED.md)。

可借鉴的是源文件与产物分开、版本与哈希固定、离线预处理、逐项回归验证的方法。具体移植代码尚无可直接复用的证据。

## Pokopia 的已知事实与未知部分

[官方产品信息](https://www.pocoapokemon.jp/sc/lineup/260227_01/)确认其平台为 **Nintendo Switch 2**，2026 年 3 月 5 日发售，由 The Pokémon Company、GAME FREAK 与 KOEI TECMO GAMES 企划开发。不能把一代 Switch 的工具兼容性直接推定到此游戏。

[任天堂官方说明](https://www.nintendo.co.jp/corporate/release/en/2026/260312.html)确认其核心包括收集材料、制作物品、建设适合宝可梦生活的环境，以及昼夜和天气变化。这支持玩法方向选择，不证明文件格式或模型可导出。

以下仍需真实样本验证：资源容器和压缩、模型格式版本、贴图编码、骨骼布局、动画关联、表情系统、材质效果、场景实例与地形数据。不能仅凭开发公司就认定使用 G1M/G1T，也不能据此承诺支持工具。

候选研究线索仅在格式匹配后再验证：

- [gust_stuff](https://github.com/eArmada8/gust_stuff)：面向 Atelier 系列 G1M 的网格处理与基础 glTF 工具；其基础 glTF 功能不能视作完整动画与材质导出保证。
- [DQB2ModelUnpacker](https://github.com/Sapphire645/DQB2ModelUnpacker)：面向 DQB2 的拆分工具，作者说明有模型和动画相关处理；未证明兼容 Pokopia。
- [Project-G1M](https://github.com/Joschuka/Project-G1M)：相关格式工具的研究入口，尚未以 Pokopia 样本验证。

没有把第三方“PC 版下载”宣传、图鉴网站或其他游戏的同名角色 Mod 视为真实 Pokopia 提取证据。

## 适合当前项目的接入路线

```mermaid
flowchart LR
  A[实际资源与版本信息] --> B[文件清单 / 格式识别]
  B --> C[网格 / 贴图 / 骨骼 / 动画转换]
  C --> D[独立 GLB 样本预览]
  D --> E[Web 材质与动作适配]
  E --> F[小花园互动验收]
  F --> G[按批次接入与离线验证]
```

1. **先验证输入。** 原始备份只读保留，记录来源、游戏版本、相对路径和 SHA-256。只有安装包时，先验证能否取得资源文件；不假定现有 Switch 工具适用。已有 GLB/FBX 和贴图时可跳过原生格式阶段。
2. **三只样本。** 优先妙蛙种子、杰尼龟、皮卡丘，验证材质、脚底、尺度、骨骼、待机和移动。它们是拟选目标，尚未获得素材。样本输出与当前 GO 资源分开，保留对照。
3. **一组场景。** 优先草地块、树、灌木、花、石头、长椅、小屋。不导入整张地图；先厘清模型与实例、碰撞、交互锚点的关系，再重建小花园。
4. **样本成立后批量转换。** 沿用全国图鉴编号映射；没有 Pokopia 对应资源的宝可梦继续使用现有版本。不能假定 Pokopia 覆盖初代 151 只。

### 现有代码中必须注意的适配点

| 文件 | 当前行为 | 后续样本验证重点 |
|---|---|---|
| `scripts/convert-models.py` | 支持 GLB/GLTF/FBX/DAE/OBJ；导出并登记模型 | 不识别未经转换的游戏原生格式；样本需显式传 `--out` 和 `--manifest` 到隔离目录 |
| `src/scene/modelUtil.ts` | 按目标高度归一化，透明材质统一改为 alpha test，单面渲染 | 花叶、玻璃、柔边等可能受损；依据真实材质调整，不能直接一律套用 |
| `src/scene/Resident.tsx` | 加载 GLB，挑选待机/行走动作并切换 | 浇水、种植、庆祝等动作需要单独状态与完成回调，不能靠换 GLB 自动获得 |
| `src/scene/hq/`、`layout.ts`、`zones.ts` | 自建场景、障碍、地形与活动区域 | 场景模型只是外观，碰撞和活动点仍需接入现有逻辑 |
| `vite.config.ts` | 自动预缓存 GLB 等文件；单文件缓存上限 8 MiB | 新资源需控体积，检查缓存覆盖和离线更新，不能把大型原始包放进 public |

初始预算沿用当前交付规范：单只模型约 8,000 三角面以内、单张贴图优先不超过 1024、GLB 优先不超过 1.5 MB；这些是目标，不是已测得的 Pokopia 数据。转换脚本会跳过带形态键网格的减面，也不会自动保证上述贴图和体积预算，必须检查产物。

## 面向 3–6 岁的首个互动样本

以下为本项目的设计建议，尚未实现，不是对 Pokopia 原玩法细节的声称。

首个闭环：**点花苗 → 选择杰尼龟帮忙 → 浇水 → 花开 → 一句可重播的英语。** 一次操作只突出一个目标，不需要复杂物品配方或精确拖放。

| 互动方向 | 小朋友的操作 | 明确反馈 | 可结合的英语 |
|---|---|---|---|
| 照料花园 | 点一下花苗 | 水滴、开花、同伴回应 | Water / Flower |
| 种植 | 选择大图标并点空地 | 自动对齐放置，立即长出植物 | Plant / Green |
| 装饰 | 两三种家具中选一个位置 | 吸附摆放，可立即撤回 | Chair / Here |
| 邀请伙伴 | 点一下空位或伙伴头像 | 同伴靠近、坐下或招手 | Come / Hello |

3–4 岁优先单步点击、图形与语音；5–6 岁再加入两步搭建和简单颜色/数量任务。保留现有休息提醒，大点击区和语音重播。不引入因离线而枯萎、长时间等待或操作失误损失资源的机制。

## 下一步的必要输入与验收

必要输入任选其一：可读取的 Pokopia 资源目录，或已导出的模型及相关贴图/动画。仅有视频、截图、图鉴页面无法还原原始网格和骨骼；只有游戏安装包也不保证可以完成后续提取。**不建议为了本次提取而仅凭该 D2R 仓库去购置设备或游戏。**

取得样本后才进行下列验收：

- 单只模型的贴图、尺度、朝向、脚底、动作循环与表情。
- 同屏多角色、树木重复实例、材质透明与动画切换的性能。
- 一次真实点击完成浇水闭环，取消/退出不重复奖励，刷新后状态正确。
- iPad 实机显示、触控与性能；断网可加载、旧缓存可升级。
- 第一批模型与现有资源对照确认后，再扩至批量。

本轮交付仅为可行性核查和接入方案。**Pokopia 资源提取、模型替换、场景与玩法移植均未完成。**
